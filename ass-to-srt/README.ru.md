# ass-to-srt

Скилл opencode, который конвертирует субтитры ASS/SSA в SRT. Один `.srt` на
каждый `.ass`/`.ssa`; архив на входе (`.zip` или `.7z`) возвращается архивом
того же типа, структура папок внутри сохраняется.

Скилл отвечает на «переведи в srt», когда файл субтитров брошен в чат:
конвертирует, проверяет начало и конец результата, называет полученные файлы
и отчитывается, что сконвертировано и что пропущено.

## Что делает

- **Оформление сохраняется.** Курсив, жирный, подчёркивание и цвета из
  inline-тегов ASS превращаются в разметку SRT (`<i>`, `<b>`, `<u>`,
  `<font color>`).
- **Реплики красятся по классу.** Обычной реплике тег не ставится — её
  рисует цвет плеера; реплика поверх кадра получает `#FFFFFF`; надпись
  (титры, таблички, текст на экране, типографика) получает `#A9A9A9`.
  Класс определяется по имени стиля, выравниванию стиля и тегам самой
  реплики. Явный цвет, написанный в ASS (`\1c`), всегда сильнее классового.
- **Тёмные цвета осветляются.** Фансабы рисуют интерфейс телефона и
  записок чёрным текстом на белом фоне, который рисуют рядом; подложки в
  SRT нет, и чёрный становится нечитаемым на телевизоре. Цвета ниже порога
  яркости поднимаются до тёмно-серого с сохранением оттенка.
- **Дубли склеиваются.** Движущаяся надпись, разбитая на отрезки пути, и
  надпись с тенью, нарисованная двумя слоями, сливаются в одну реплику;
  яркое оформление побеждает. Одинаковые слова после настоящей паузы
  остаются отдельными репликами.
- **Варианты для плееров, которые режут разметку.** `--variant plain`
  пишет голый текст без тегов; `--variant tags` пишет оформление без
  классовых цветов; `--variant both` даёт оба файла за один прогон. По
  умолчанию `colors` (теги плюс классовые цвета) — проверено на телевизоре
  автора (LG OLED), где теги воспроизводятся корректно.
- **Размера шрифта в SRT нет.** `<font size>` проигрыватели не понимают,
  скрипт его не пишет; размер — настройка плеера.

Векторные рисунки (`\p1 … \p0`) удаляются, караоке сохраняет весь текст без
послоговой подсветки, кодировка определяется (`utf-8`, `utf-16`, `cp1251`,
…) и видна только в `--json` отчёте.

## Требования

| Инструмент | Зачем | Примечания |
|------------|-------|------------|
| `python3` | сам конвертер | только стандартная библиотека, pip не нужен |
| `7z` | только для входа `.7z` | p7zip; `.zip` работает на стандартной библиотеке |

Ничего больше. Preflight-скрипта нет: два инструмента проверяются вручную.
На cygwin скрипт предпочитает `/usr/bin/7z` windows-ному `7z.exe` с PATH,
потому что windows-сборка не понимает пути `/cygdrive/...`.

## Установка

Скиллу нужно лежать в папке скиллов opencode.

```bash
git clone git@github.com:quangorn/agents.git
bash agents/ass-to-srt/install.sh
```

Скилл копируется в `~/.config/opencode/skills/ass-to-srt` (на Windows — под
нативный профиль пользователя, откуда opencode читает конфиг). Копия, не
перенос: репозиторий продолжает работать как клон. Если цель уже существует,
скрипт отказывается и говорит об этом.

Или вручную:

```bash
mkdir -p ~/.config/opencode/skills
cp -r agents/ass-to-srt/.opencode/skills/ass-to-srt ~/.config/opencode/skills/
```

Или просто открой `agents/ass-to-srt` в opencode и используй из project scope.

## Использование

Через opencode: брось файл в чат и попроси SRT обычными словами:

> переведи этот ass в srt

Агент пройдёт по скиллу: конвертация, проверка начала и конца результата,
имена полученных файлов, отчёт по числам.

Из командной строки скрипт работает и сам по себе. Запускай
`scripts/convert.py` из папки скилла:

```bash
# один .ass -> один .srt
python3 ~/.config/opencode/skills/ass-to-srt/scripts/convert.py \
  --input "movie.en.ass"

# несколько входов за один прогон
python3 .../convert.py --input "a.ass" --input "b.ssa" --out-dir "out/"

# архив на входе, архив того же типа на выходе
python3 .../convert.py --input "subs.zip"
python3 .../convert.py --input "subs.7z"

# плеер, который режет разметку: голый текст без тегов
python3 .../convert.py --input "movie.ass" --variant plain

# оба варианта за один прогон -> movie.colors.srt + movie.plain.srt
python3 .../convert.py --input "movie.ass" --variant both

# классовые цвета под конкретный плеер
python3 .../convert.py --input "movie.ass" \
  --sign-color "#A9A9A9" --ontop-color "#FFFFFF"
```

### Опции

| Опция | Значение |
|-------|----------|
| `--input FILE` | `.ass`, `.ssa`, `.zip` или `.7z`; можно повторять |
| `--out-dir DIR` | куда писать результат, по умолчанию `./subtitle-output/<имя входа>/` |
| `--variant` | `colors` (дефолт) \| `tags` \| `plain`; `both` = `colors,plain` |
| `--sign-color` / `--ontop-color` | классовые цвета, `#RRGGBB`; `none` отключает тег |
| `--no-merge` | не склеивать дубли реплик |
| `--merge-tolerance MS` | зазор, который ещё считается дублем; по умолчанию 250 мс, `0` — только точное смыкание |
| `--min-brightness N` | поднимать цвета темнее N до тёмно-серого, по умолчанию 96; `0` отключает |
| `--json` | структурированный отчёт вместо human-readable |
| `--selftest` | прогнать встроенные проверки (74) и выйти |

Ничего за пределами `--out-dir` не пишется, поэтому файл из чата считается
read-only.

### Коды возврата

| код | смысл |
|-----|-------|
| 0 | всё сконвертировано |
| 1 | часть файлов внутри архива не сконвертирована (отчёт называет их через `x`) |
| 2 | вход не обработан целиком (нет `7z`, в архиве нет `.ass/.ssa`, файл не найден) |

### Связь с другими проектами

Проект `video-convert` вызывает `scripts/convert.py` этого скилла, чтобы
делать `.srt` sidecar из ASS-потока субтитров, — два проекта синхронизированы.

## Документация

  выглядит неправильно.
