# Правила конвертации ASS/SSA → SRT

Справочник для случаев, когда результат выглядит неправильно. Основной поток
описан в `SKILL.md`; сюда стоит заглядывать только когда что-то сломалось.

## Что вообще происходит

1. **Декодирование.** BOM → `utf-8-sig` / `utf-16` (LE и BE). Иначе строгий `utf-8`.
   Иначе подсказка `chardet` (если установлен). Иначе `cp1251` → `cp1252` → `latin-1`.
   Кодировка видна в отчёте: `кодировка cp1251`.
2. **Разбор.** Читается только секция `[Events]`. Порядок колонок берётся из строки
   `Format:` (регистр не важен). Если её нет — стандартный v4+:
   `Layer, Start, End, Style, Name, MarginL, MarginR, MarginV, Effect, Text`.
   Строка делится по запятым ровно на `len(Format)` полей, поэтому запятые внутри
   текста реплики не ломают разбор.
3. **Стили.** Текст экранируется, затем теги ASS превращаются в HTML-теги SRT.
4. **Сборка.** UTF-8 без BOM, переводы строк LF, нумерация с 1, пустая строка между
   репликами, сортировка по времени начала.

## Таблица тегов

| ASS | `--variant tags` | `--variant plain` |
|---|---|---|
| `\i1` / `\i0` | `<i>` / `</i>` | вырезать |
| `\b1` / `\b0` | `<b>` / `</b>` | вырезать |
| `\u1` / `\u0` | `<u>` / `</u>` | вырезать |
| `\1c&H0000FF&`, `\c&H...&` | `<font color="#RRGGBB">` | вырезать |
| `\1c&Hblue&` (имя цвета) | `<font color="#0000FF">` | вырезать |
| `\2c` `\3c` `\4c` `\1a` | вырезать | вырезать |
| `\r` / `\rStyle` | закрыть открытые `<i> <b> <u> <font>` | вырезать |
| `\N`, `\n` | настоящий перенос строки | то же |
| `\h` | неразрывный пробел U+00A0 | то же |
| `\p1 … \p0` | блок удаляется целиком | то же |
| `\k \kf \ko \kt` | вырезать, текст Karaoke сохраняется | то же |
| `\an \a \pos \move \org \f \fs \fscx \fscy \sp \t \q \o \blur \bord \be \shad \fax \fay \fad` | вырезать | вырезать |
| «сиротский» `\i0` / `\b0` вне фигурных скобок | вырезать | вырезать |

**Про цвета.** ASS хранит цвет как `&HBBGGRR&`, то есть BGR. Поэтому `&H0000FF&` —
это **красный** (`#FF0000`), а `&HFF0000&` — синий (`#0000FF`). Не путать: в SRT
и в HTML порядок уже RGB.

**Про позиционирование.** `\pos`, `\move`, `\an` в SRT непередаваемы. Реплика, которая
в ASS висела в углу экрана, в SRT станет обычной строкой. Это ожидаемо.

**Про рисунки.** Между `{\p1}` и `{\p0}` лежат данные векторного рисунка, а не текст.
Они удаляются в обоих вариантах, а число таких блоков попадает в отчёт как `рисунков N`.

## Классы реплик (`--variant colors`, дефолт)

В ASS нет поля «это надпись»: тип события бывает только `Dialogue` и `Comment`, и `Comment`
означает «не рисовать», а не «надпись». Разделять приходится по косвенным признакам, и
порядок проверок такой:

1. **Имя стиля.** `sign`, `typeset`, `telop`, `title`, `eyecatch`, `credit`, `karaoke`,
   `lyric`, `insert`, `notice`, `caption`, `os`, `song`, `note` → надпись.
   `top`, `scroll`, `overlay` → реплика поверх кадра.
   `default`, `main`, `italic`, `flashback`, `dialog`, `narrat` → обычная реплика.
2. **Выравнивание стиля.** Для речевого стиля `Alignment` 7, 8 или 9 означает верх кадра,
   то есть реплику поверх кадра.
3. **Теги самой реплики.** `\an7..9`, `\move` или `\pos` выше середины `PlayResY`
   поднимают реплику из диалога в «поверх кадра»; блок рисунка `\p1` делает её надписью.
4. **Стили с бессмысленными именами.** Если имя ни о чём не говорит, стиль судится по своим
   репликам: доля событий с `\pos`, `\move`, `\org`, `\fad`, `\clip`, `\t` или рисунком
   выше половины — надпись, ниже — реплика.

На выборке из 18 файлов (Steins;Gate 0 и Jujutsu Kaisen, 8016 событий) координаты как
единственный признак дали точность 93 % при полноте 81 %: без координат остаются караоке-стили
(`World-Line`, `Fatima`) с одним `\fad`, а ложные срабатывания дают реплики, которые группа
специально сдвинула (`Main` с `\pos`, `On Top`). Добавление `\fad` и рисунка поднимает
полноту до 99 %, а решение на уровне стиля убирает ложные срабатывания совсем.

**Цвета.** Обычная реплика идёт без тега (цвет плеера), реплика поверх кадра — `#FFFFFF`,
надпись — `#A9A9A9`; меняется через `--ontop-color` и `--sign-color`, `none` отключает тег.
Явный `\1c` в тексте реплики сильнее классового цвета и проходит обычное осветление.
Склейка дублей считает класс частью ключа, поэтому одинаковые слова в разных классах не
сливаются в одну реплику.

## Что отбрасывается и как это видно

| Причина | Счётчик в отчёте | Примечание |
|---|---|---|
| `Comment:`, `Picture:`, `Sound:`, `Movie:`, `Command:` | — | не попадают в `.srt` никогда |
| `end <= start` или нечитаемое время | `отброшено N` | частая болезнь кривых сборок |
| после очистки не осталось символов | `пустых N` | были только теги или рисунок |
| неразобранная строка `Dialogue:` | `отброшено N` | полей меньше, чем в `Format:` |
| векторный рисунок | `рисунков N` | сам рисунок потерян, текст рядом сохранён |
| караоке `\k` | `караоке N` | текст на месте, тайминги по словам — нет |
| склейка дублей | `склеено N` | сколько реплик влилось в предыдущую |
| осветление цвета | `осветлено N` | цвета темнее порога подняты до тёмно-серого |

`караоке N > 0` — это нормально для аниме-дорожек: в SRT просто показывается вся
реплика целиком, без подсветки по слогам.

## Склейка дублей

Один и тот же текст в ASS попадает в `.srt` несколькими репликами по двум причинам,
и обе убираются автоматически:

- **Движущаяся надпись** разбита на отрезки пути — по реплике на участок перемещения.
  Плеер показывает одни и те же слова два-три раза одновременно.
- **Надпись с тенью** нарисована двумя слоями: основной (`Layer 1`, светлый, тонкий
  `\blur`) и теневой (`Layer 0`, тёмный, с размытием). У слоёв свои цвета и свои
  тайм-коды, отличающиеся на несколько кадров.

Правило склейки:

- реплики считаются одинаковыми, если совпадает **читаемый текст**; теги вроде
  `<font color>` и `<b>` на совпадение не влияют, потому что именно ими слои
  отличаются друг от друга, а в SRT тени нет;
- склеиваются, если интервалы **перекрываются**, **смыкаются** или разделены зазором
  меньше допуска — по умолчанию 250 мс (`--merge-tolerance MS`, `0` отключает допуск);
- склеенная реплика занимает объединение промежутков, оформление берётся от первой;
- одинаковые слова после настоящей паузы остаются отдельными репликами.

Отключается целиком флагом `--no-merge`, если нужен исходный вид «как в ASS».

### Какой вариант оформления выживает

Склеенная реплика сохраняет **более яркий** вариант, а не тот, что попался первым: яркость
считается как 0,299·R + 0,587·G + 0,114·B. Реплика без явного `<font color>` считается
самой яркой — её рисует сам плеер своим фирменным цветом. При полном равенстве остаётся
первая, чтобы вывод был воспроизводимым. Так тень никогда не побеждает основной слой.

### Осветление слишком тёмного

Фансабы рисуют интерфейс телефона и записок как почти чёрный текст, но в ASS рядом нарисован
и белый фон, на который этот текст рассчитан. В SRT подложки нет, и остаётся чёрный текст
поверх картинки — на телевизоре он нечитаем.

Поэтому любой цвет с яркостью ниже порога поднимается до этого порога: по умолчанию **96**.
Флаг `--min-brightness N` меняет порог, `--min-brightness 0` отключает осветление совсем.
Счётчик `осветлено N` в отчёте показывает, сколько цветов поднято.

Оттенок при этом сохраняется. Три канала умножаются на один коэффициент `порог / яркость`,
поэтому пропорции между ними — а значит и сам цвет — остаются прежними:

```
#8E0D26 → #FA1743   яркость 54 → 96, оттенок 348° → 348°
#63000F → #FF153F   яркость 31 → 96, оттенок 351° → 349°
#0B1115 → #436881   яркость 16 → 96, оттенок 204° → 204°
```

Насыщенный цвет упирается в 255 и простым масштабом до порога не добирается — тогда
недостающее добавляется белым: оттенок остаётся узнаваемым, цвет слегка высветляется.
Чистый чёрный оттенка не имеет и становится нейтральным серым.

## Имена выходных файлов

По умолчанию делается один файл, имя не меняется относительно исходного:

| Вход | результат по умолчанию (`colors`) |
|---|---|
| `movie.en.ass` | `movie.en.srt` |
| `pack.zip` | `pack.zip` |
| `pack.7z` | `pack.7z` |

Суффикс `.colors`/`.plain` в имени появляется только при `--variant both`, если явно попросить
оба варианта сразу; при одиночном `--variant plain` выходит `movie.en.srt` с голым текстом.

Внутри архива структура папок сохраняется, расширение меняется `.ass` → `.srt`.
Не-субтитры (`.txt`, `.jpg`, уже готовые `.srt`) в выход не попадают.

Коллизия: `a.ass` и `a.ssa` в одной папке дали бы один `a.srt`. Второй получает
`a.ssa.srt`, третьего — счётчик (`a-2.srt`). Факт виден в листинге выхода.

## Диагностика

**Пустой или почти пустой `.srt` при непустом `.ass`.** Проверь секцию `[Events]`
(регистр секции важен, имя колонок — нет) и наличие строки `Format:`. Файл `.ssa`
старого формата без `Layer` тоже разбирается — порядок колонок читается из `Format:`.

**Кракозябры в тексте.** Смотри колонку кодировки в `--json`-отчёте. Если файл в
`shift-jis` или `big5`, добавь кодировку в `decode_bytes` в `scripts/ass2srt.py`.

**`&amp;` вместо `&`.** Так и задумано: текст экранируется, чтобы проигрыватель не
воспринял `<` и `&` как разметку. Проигрыватель, который не раскрывает entities,
покажет `&amp;` буквально — это повод перейти на `plain`-подход, но не баг.

**Теги не работают на проигрывателе.** Часть плееров не рендерит HTML в SRT — на
телевизоре автора (LG OLED) теги воспроизводятся, поэтому дефолт `tags`. Если попадётся
плеер, который их режет, разовый выход — `--variant plain`.

**Ошибка `7z не найден`.** `sudo apt-get install -y p7zip-full`. `.zip` при этом
продолжает работать — он на стандартной библиотеке.

## Проверка самого конвертера

```bash
python3 "<skill-dir>/scripts/convert.py" --selftest
```

72 проверки: порядок колонок, все форматы времени, переводы строк, вложенные теги,
цвета (в том числе по имени), сброс стиля, рисунки, караоке, `plain`-вариант,
экранирование, cp1251 / UTF-16 / UTF-8 с BOM, отбраковка `Comment:` и битых строк,
классы реплик (цвета, явный цвет, `\an8`, рисунок),
коллизии имён, склейка (движение, тени, границы допуска, выбор более яркого), осветление чёрного, круговой
прогон zip и 7z. Код возврата `0` — все прошли.
