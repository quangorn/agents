# ASS/SSA → SRT

Всё делает `scripts/convert.py` из папки, где лежит этот файл. Дальше
`<skill-dir>` — путь к этой папке, скрипт: `<skill-dir>/scripts/convert.py`.
Зависимостей нет: конвертация и zip — стандартная библиотека Python 3, для `.7z` нужен `7z`
(если на машине есть и `/usr/bin/7z` из cygwin, и `7z.exe`, скрипт сам предпочитает cygwin-сборку,
потому что Windows-версия не понимает пути `/cygdrive/...`).

## 1. Возьми путь к входному файлу

Путь бери из сообщения пользователя (когда файл перетащен в чат) или из рабочей папки сессии.
Если пути нет и непонятно, какой именно файл нужен — спроси; по диску наугад не ищи.

Файл, полученный из чата, считай read-only: не изменяй и не удаляй его, только читай.

## 2. Сконвертируй

Запускай из рабочей папки сессии:

```bash
python3 "<skill-dir>/scripts/convert.py" \
  --input "<путь к файлу>" [--input "<второй путь>"] \
  --out-dir "<рабочая папка>/subtitle-output/<имя входа>/"
```

После установки скилла полный путь к скрипту:
`~/.config/opencode/skills/ass-to-srt/scripts/convert.py`. Рабочий пример:
В Windows тот же путь: `%USERPROFILE%\.config\opencode\skills\ass-to-srt\scripts\convert.py`.

```bash
python3 ~/.config/opencode/skills/ass-to-srt/scripts/convert.py \
  --input "movie.en.ass" --out-dir "<рабочая папка>/subtitle-output/movie.en/"
```

Один запуск принимает несколько `--input`. Определение по расширению: `.ass`/`.ssa` — одиночный файл, `.zip`/`.7z` — архив на входе и архив того же типа на выходе.

Коды возврата:

| код | смысл | что делать |
|---|---|---|
| 0 | всё сконвертировано | идти к проверке |
| 1 | часть файлов внутри архива не сконвертирована | отдать результат и назвать строки с `x` из отчёта |
| 2 | вход не обработан целиком | разобрать строку с `[n/n]` из отчёта: нет `7z`, в архиве нет `.ass/.ssa`, файл не найден |

## 3. Проверь результат

Не выводи файлы в чат целиком — только края:

```bash
head -c 400 "<файл>.srt"; tail -c 200 "<файл>.srt"
python3 -m zipfile -l "<архив>.zip"   # или: /usr/bin/7z l -ba "<архив>.7z"
```

Ищи в начале: `1`, затем `00:00:01,200 --> …`, затем читаемый текст. Если вместо текста теги или пустота — прочитай `references/conversion-rules.md`.

## 4. Отдай результат

Назови получившиеся файлы и их полные пути (их можно открыть в проводнике / отдать дальше).
Больше 4 файлов — перечисли путями, а не содержимым. Ничего не копируй и не переименовывай без просьбы.

## 5. Отчитайся

Две-три строки: что сконвертировано (файлов, реплик) и что и почему пропущено.

## Правила, которые нельзя нарушать

- Входные файлы не перезаписывать: результат всегда пишется в `--out-dir`.
- Не писать за пределы рабочей папки сессии без отдельного подтверждения.
- Путь, полученный из чата, — read-only копия: не изменять и не удалять её, только читать.

## Оформление: почему один вариант

По умолчанию делается **один** `.srt` с сохранённым оформлением: курсив, жирный и цвета из
ASS переносятся в `<i>`, `<b>`, `<font color>`, а реплики дополнительно красятся по классу
(диалог / поверх кадра / надпись). Это проверено на телевизоре автора (LG OLED) — теги
воспроизводятся корректно, поэтому вариант без оформления (`--variant plain`) больше не
делается. Он остался в коде на случай, если попадётся проигрыватель, который режет разметку:

```bash
python3 "<skill-dir>/scripts/convert.py" --input "<путь>" --variant plain
```

Вариант `tags` (оформление без классовых цветов) тоже остался: `--variant tags`.
`--variant both` даёт сразу два файла: `colors` (дефолт) и `plain`.

Подробности про то, что именно переносится: `references/conversion-rules.md`.

## Классы реплик: `--variant colors` (дефолт)

Обычный `.srt` не отличает надпись от реплики, поэтому вариант по умолчанию красит три класса
по-разному:

| класс | что это | цвет в SRT |
|---|---|---|
| обычная реплика | диалог в нижней полосе | тег не ставится — цвет плеера |
| реплика поверх кадра | диалог, поднятый в кадр (`\pos`, `\an7..9`, стиль `* - Top`, `On Top`, `Narration`) | `<font color="#FFFFFF">` |
| надпись | титры, таблички, `OS`, `sign_*`, `Title`, караоке | `<font color="#A9A9A9">` |

Класс определяется по имени стиля, затем по выравниванию стиля и по тегам самой реплики;
для стилей с ничего не говорящими именами работает признак «реплика размещена, анимирована
или нарисована». Явный цвет, написанный в ASS (`\1c`), всегда сильнее классового.
Полностью правила разобраны в `references/conversion-rules.md`.

Классовые цвета подбираются под конкретный плеер:

```bash
python3 "<skill-dir>/scripts/convert.py" --input "<путь>" \
  --sign-color "#A9A9A9" --ontop-color "#FFFFFF"
```

Размер шрифта в SRT не задаётся: `<font size>` проигрыватели не понимают, такой
возможности в скрипте нет. Размер — только настройками плеера.
