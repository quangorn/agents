# dv-mkv-to-mp4

Скилл opencode, который конвертирует MKV с Dolby Vision в MP4 с Dolby Vision,
воспроизводимый на LG OLED, Nvidia Shield и других устройствах с поддержкой DV.

Видео **никогда не перекодируется**. HEVC-поток вынимается из контейнера
Matroska как есть, RPU Dolby Vision остаётся внутри, а GPAC собирает обратно
MP4 с корректной DV-сигнализацией. Результат побитово совпадает с исходником,
а конвертация 4K занимает примерно столько же времени, сколько копирование.

Сверх этого скилл закрывает то, что обычно делает результат неудобным для
просмотра на телевизоре:

- показывает дорожки аудио и субтитров и даёт выбрать, какие оставить
- перекодирует FLAC и DTS в AC-3, потому что многие телевизоры их не умеют
- выкладывает субтитры рядом с видео отдельными файлами, а не внутрь
- если Dolby Vision в исходнике нет вообще, копирует видео без изменений и
  говорит об этом, а не изображает DV-конвертацию

## Требования

| Инструмент | Зачем | Примечания |
|------------|-------|------------|
| `ffmpeg` / `ffprobe` | извлечение потоков и муксинг | 4.4 или новее |
| `MP4Box` (GPAC) | сборка MP4 | GPAC 2 или новее, см. ниже |
| `dovi_tool` | определение RPU Dolby Vision | [quietvoid/dovi_tool](https://github.com/quietvoid/dovi_tool) |
| `mkvextract` | извлечение глав | MKVToolNix |
| `mediainfo` | проверка результата | MediaArea |
| `jq` | разбор вывода ffprobe | |

`bash scripts/preflight.sh` проверяет всё это и печатает точный список
недостающего, чтобы не приходилось гадать.

`hdr10plus_tool`, `bc`, `dotnet` и `PgsToSrt` **не нужны**. Они относятся к
HDR10+ и OCR-распознаванию PGS, которых здесь нет.

### Про версии MP4Box

Исходный проект, откуда взят этот воркфлоу, закрепляет MP4Box 1.0.1, потому
что в GPAC 2 изменилась опция Dolby Vision. Старая синтаксиса `:dv-profile=8`
теперь падает:

```
DV profile 8 must indicate a compatibility mode `hdr10`, `bt709` or `hlg2100`
Failure while setting DV profile: Bad Parameter
```

Актуальная синтаксиса — `:dvp=8.1.hdr10`, где часть после точки это
идентификатор совместимости базового слоя. Скилл выводит его из transfer
characteristics базового слоя, поэтому работает с современным GPAC. MP4Box
1.0.1 не требуется.

## Установка

```bash
git clone git@github.com:quangorn/agents.git
bash agents/dv-mkv-to-mp4/install.sh
```

Или вручную:

```bash
mkdir -p ~/.config/opencode/skills
cp -r agents/dv-mkv-to-mp4/.opencode/skills/dv-mkv-to-mp4 ~/.config/opencode/skills/
```

Или просто открой `agents/dv-mkv-to-mp4` в opencode и используй из project scope.

## Использование

Через opencode, обычным запросом:

> сконвертируй этот mkv в mp4 с Dolby Vision

Агент пройдёт по скиллу: preflight, таблица дорожек, вопрос о выборе, вопрос
о папке назначения, конвертация, проверка результата.

Из командной строки скрипты работают и сами по себе:

```bash
# что в файле и есть ли в нём Dolby Vision
bash scripts/list-tracks.sh "movie.mkv"
bash scripts/dv2mp4.sh -i "movie.mkv" --probe

# конвертация
bash scripts/dv2mp4.sh -i "movie.mkv" -o "movie.DV-MP4.mp4" -a 1,4,5 -s 6,7,8
```

### Опции

| Опция | Значение |
|--------|----------|
| `-i, --input FILE` | исходный MKV, обязательно |
| `-o, --output FILE` | выходной MP4. Необязательно: `<base>.DV-MP4.mp4` для DV-исходника, `<base>.mp4` иначе |
| `-a, --audio IDS` | номера аудиодорожек, по умолчанию все |
| `-s, --subs IDS` | номера субтитров для выгрузки, по умолчанию none. ASS выгружается всегда |
| `-l, --langs LIST` | фильтр по языку, например `rus,eng` |
| `--probe` | показать, есть ли Dolby Vision, и выйти |
| `--asm` | дополнительно записать `.asm.mkv` с аудио и субтитрами без видео |
| `--remove-source` | удалить исходник после успешной конвертации |
| `--keep` | не удалять временную рабочую папку |
| `--title TEXT` | название, записываемое в MP4 |
| `--dvp VALUE` | принудительное значение Dolby Vision для GPAC, например `8.1.hdr10` |
| `--tmp DIR` | куда класть временные файлы, по умолчанию `~/tmp` |

Номера дорожек — это **абсолютные индексы потоков**, те же, что ждёт
`ffmpeg -map 0:ID`. Таблица дорожек их печатает.

## Что делает скрипт

1. **Preflight.** Проверяет наличие всех инструментов.
2. **Извлекает видео** как annexb-поток HEVC во временную папку. Для
   однослойных профилей 4, 5 и 8 RPU Dolby Vision уже внутри. Для профиля 7
   дополнительно извлекается enhancement layer, и RPU вклеивается в базовый
   слой через `dovi_tool`.
3. **Определяет Dolby Vision** через `dovi_tool extract-rpu` и
   `dovi_tool info`. mediainfo для этого намеренно не используется: он
   перестаёт писать «Dolby Vision» даже на перерезанных MKV, где RPU цел.
4. **Конвертирует аудио.** `ac3`, `eac3`, `aac` и `mp3` копируются как есть.
   `flac` становится AC-3 с 640 кбит/с, это максимум AC-3. `dts` становится
   AC-3 с битрейтом источника, если он ниже 640 кбит/с, иначе с максимумом
   640 кбит/с и предупреждением. `truehd` и прочее — в E-AC-3 1024 кбит/с.
5. **Выгружает субтитры** отдельными файлами рядом с видео. `subrip` → `.srt`,
   ASS → `.ass` плюс производный `.srt`, PGS → `.sup` без распознавания.
6. **Собирает MP4** с профилем Dolby Vision и брендом `dby1`.
7. **Проверяет результат.** В выходе обязан быть бокс `DolbyVision`, иначе
   скрипт удаляет файл и падает. Для исходника без DV проверка обратная: бокса
   `DolbyVision` быть не должно.
8. **Убирает за собой.** Все промежуточные файлы живут во временной папке под
   `~/tmp` и удаляются при выходе, в том числе при ошибке.

## Профили Dolby Vision

| Профиль | Бренд | Совместимость базового слоя | Статус |
|---------|-------|----------------------------|--------|
| 8 | `dvhe.08` | hdr10, bt709 или hlg2100 | проверен на реальном железе |
| 7 | `dvhe.07` | HDR10 | перенесено из dvmkv2mp4, здесь не проверено |
| 5 | `dvhe.05` | нет | перенесено из dvmkv2mp4, здесь не проверено |
| 4 | `dvhe.04` | SDR или HDR | перенесено из dvmkv2mp4, здесь не проверено |

Чистый HDR10+ без Dolby Vision в Dolby Vision здесь не превращается. Исходник
без DV всё равно ремуксится, видео копируется без изменений, и в выводе об
этом сказано.
