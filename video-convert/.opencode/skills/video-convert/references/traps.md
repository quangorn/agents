# Ловушки

Каждый пункт получен в реальной сессии на этой машине (Windows + Cygwin bash,
ffmpeg с NVENC, GPAC, dovi_tool, MKVToolNix, jq.exe). Не «упрощать» ни один из
них: все они стоят денег в виде пустых файлов, неправильных дорожек или
ложных выводов.

## Проверенные ловушки (дословно)

- `-avoid_negative_ts make_window` → `Undefined constant or missing '(' in
  'make_window'`; писать `1` / `make_zero`
- `-rc vbr_hq` → `Error opening output files: Invalid argument`
- `-profile:v main` в MKV → «not a suitable output format»; `-f mkv` невалидно
  → `matroska`
- `-c:a truehd` / `-c:a dca` → experimental, нужен `-strict -2`; без него rc=127
  и пустой файл
- PCM пишется и в MKV, и в MP4 (ffmpeg rc=0, проверено), так что ограничение не
  контейнер, а поддержка TV
- `-ss`/`-t` на входе **не** режут субтитры — работает только `-t` на выходе
  (`-c:s srt -t 20`)
- ffmpeg **не** кодирует PGS и не пишет `.sup`; `pgssub` — только decoder.
  Рабочий путь:
  ```
  FF -ss <t> -t 20 -i src.mkv -map 0:<sub> -c:s copy pgstemp.mkv
  mkvextract <pgstemp windows path> tracks 0:<name>.jpn.sup   # ID из `mkvmerge -i`, не предполагать
  ```
  magic `50 47` = "PG"
- mkvmerge/mkvextract/ffprobe падают на путях `/cygdrive/...` → нужен
  `cygpath -m`; closing quote после `"$(cygpath -m ...)"` обязателен
- write tool сохраняет CRLF → перед запуском bash делать `sed -i 's/\r$//'`

## cygpath: native-инструменты не понимают Cygwin-пути

`ffmpeg.exe`, `MP4Box.exe`, `dovi_tool.exe`, `mkvextract.exe` — Windows-бинарники.
Cygwin-путь они не понимают и падают:

```
ffmpeg ... -f hevc ~/tmp/dv2mp4.XXXX/BL_RPU.hevc
```

→ `No such file or directory`. Правило: `cygpath -m` (`~/tmp/x` → `D:/tmp/x`) для
каждого аргумента, который уходит в native-инструмент. Bash-встроенные команды
(перенаправления, `mktemp`, `cp`) остаются на Cygwin-пути. `mktemp -d` возвращает
Cygwin-путь, в который ffmpeg не может писать — это тоже нормализуется.

## Windows `jq.exe` выдаёт CRLF

Каждое значение из jq приходит с хвостовым `\r`, и это тихо ломает валидацию, а
не выдаёт ошибку:

```
"rus\r"        fails ^[a-z]{2,3}$      -> язык показан как "und"
"448000\r"     fails ^[0-9]+$          -> битрейт показан как "unknown"
"subrip\r"     misses the case arms    -> экспортирован как "unsupported"
```

Вывод jq всегда прогонять через `tr -d '\r'`. Скрипты централизуют это в одной
функции.

## В jq число `0` — truthy

```jq
if .disposition.forced then "1" else "0" end     # wrong: every track is "1"
if .disposition.forced == 1 then "1" else "0" end # right
```

В jq falsy только `false` и `null`. Проверять `== 1`, а не «истинность».

## `ffprobe -select_streams a:N` — НЕ абсолютный индекс

Самая опасная ловушка, потому что она молчит:

- `ffprobe -select_streams a -show_entries stream=index` печатает **абсолютные**
  индексы потоков (`1,2,3,4,5`).
- `ffprobe -select_streams a:1` — индекс **относительно типа «аудио»**.

Смешивание сдвигает все поля на число предшествующих потоков: аудиодорожка `1`
показывала данные дорожки `2`, одна дорожка читалась как пустая. `ffmpeg -map 0:N`
— абсолютный индекс, так что извлечение было правильным, а метаданные — ложными.

Рабочий путь: прочитать все потоки один раз в JSON и искать
`select(.index==$idx)`. Для lookup'а `-select_streams a:ID` не использовать
никогда.

## Смежные

- `-disposition:a:N` и `-disposition:s:N` — индекс **по типу потока** (N-й аудио
  поток выхода), как `-c:a:N`, а не абсолютный индекс `-map`-порядка, который
  использует `-ac:N`. Проверено на этой сборке. Снимается флаг дефолтом с
  минусом: `-disposition:a:0 -default` (проверено: источник с default на 2-м
  аудио, после `-disposition:a:1 default -disposition:a:0 -default` флаг
  переехал). ffmpeg **копирует** флаги источника, поэтому снятие — реальная
  запись, а не пустая операция.
- `jq.exe` и `MP4Box.exe` — native: **не** понимают `/cygdrive/...`, в том числе
  файлы, которые jq читает аргументом, и файл программы `-f`. Все пути, которые
  уходят в native-инструмент, через `cygpath -m`; bash-редирект (`> out.json`)
  остаётся на cygwin-пути.
- `jq -s prog "$WORK"/*.json` с именем «ep 01.json»: незакавыченный glob
  разбивает имя на два слова, jq открывает несуществующий `ep` и `01.json` в
  текущей папке. Файлы с пробелом — норма для папок сериалов: собирать массив
  путей и писать `"${DUMPS[@]}"`.
- `gsub("|";"\\|")` в jq: `|` в regex матчит пустую строку, и экранирование
  попадает **между каждым символом** («\|O\|r\|i\|g\|i\|n\|a\|l»). Паттерн
  писать `[|]`: `gsub("[|]";"\\|")`.
- `group_by(.sig)` возвращает группы **объектов**; `.[0]` — это группа, а не
  подпись. Подпись берётся как `.[0].sig`, а «референсный файл» — `.[0]`. Ошибка
  молчит: `$ref` не находится, и jq выдаёт «Cannot iterate over null».
- `bash "${CMD[@]}"`, когда первый элемент массива уже `bash`: bash получает
  скрипт с именем `bash` → rc=126, «не удаётся запустить бинарный файл».
  Запускать `"${CMD[@]}"` напрямую.
- Sidecar `.srt`, сделанный из `.ass`, **теряет title-тег** дорожки: keyword
  plex-tracks по нему не работает, выбор только по языку
  (`--subtitle ru --subtitle-external`).
- plex-tracks печатает JSON-отчёт в stdout, сообщения — в stderr. Слить их
  (`2>&1 > report.json`) значит испортить JSON, из которого работает `--undo`:
  stderr писать в отдельный лог (`2>>log`).
- Локальный админ-токен Plex (`.LocalAdminToken`) пишет `POST /library/parts` на
  этой машине — проверено. Неверный `streamId` отвечает **HTTP 400** (PMS
  2025.x), старый PMS отвечал 200 и ничего не менял; ответу не верить, перечитывать
  `/library/metadata/{ratingKey}`.
- Префиксная логика языка `ru↔rus` ломается на `ja`, `zh`, `es`: `ja` никогда не
  начинается с `jpn`, `zh` с `chi`, `es` с `spa`. `--default-audio ja` не находил
  ничего и **молча снимал все аудио-дефолты с кодом 0**. Нужна таблица алиасов
  (2-буквенный ISO → 3-буквенный тег), общая с `LANG_ALIASES` plex-tracks.
- Индексирование библиотеки подтверждать **именем файла**, не числом эпизодов:
  Plex может показать столько же серий, сколько файлов, от совершенно другого шоу,
  и прогон по числу разрешит писать plex-tracks по чужому списку. Каждое имя
  конвертированного выхода должно быть среди `file` план-элемента; путь от Plex —
  windows, базовое имя резать и по `/`, и по `\`.
- refresh слать в секцию, покрывающую **выходную** папку, а не `--in-dir`: скачанный
  сезон лежит в другом дереве, совпадение только по источнику даёт пустой KEY, refresh
  не уходит, и plex-tracks пишет по состоянию до скана.
- Переменную, которая присваивается только внутри `if [[ -n "$TOK" ]]`, задать
  заранее (`KEY=""`): под `set -u` незаданная переменная убивает скрипт в самом
  конце прогона, после всех конвертаций — итоговый отчёт теряется.
- Строку «report for rollback» печатать только когда этот прогон реально применял:
  отчёт прошлого прогона лежит рядом с `batch.log`, и его показ как откат прогона,
  который ничего не писал, — ложь.

- `-show_entries` вместе с `-show_streams` на ffmpeg 4.4 тихо теряет поля:
  `language` исчезал, таблица субтитров становилась бесполезной. Использовать
  plain `-show_streams -of json` и фильтровать через jq.
- Записи дорожек не собирать через `|`: в названиях очень часто встречается
  `Дубляж | Some Studio`, и поля разъезжаются. Разделитель — US (`0x1f`).
- `${x//|/\|}` **не** экранирует: bash читает `\|` в замене как обычную `|`,
  и анти-слеш исчезает молча, строка markdown-таблицы разъезжается. Рабочая
  форма — `printf '%s' "$x" | sed 's/[|]/\\|/g'`. В jq тот же эффект даёт
  паттерн `|` (матчит пустую строку), там нужен `[|]`.
- `while IFS=$'\t' read -r a b c` схлопывает серии табуляций: пустые поля
  (пустое название, пустой язык) сдвигают всё вправо. Использовать JSON-строки.
- Долгое извлечение должно печатать heartbeat (каждые 20 s), иначе лог выглядит
  зависшим и сессия делает ложный вывод о «застрявшем» скрипте.
